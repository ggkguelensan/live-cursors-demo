# Side by side — live cursors demo

Два независимых клиента одного документа, показанные рядом. Maya пишет, Leo
выделяет и редактирует её фразу, Nora добавляет тег и реагирует на результат.
Участники набирают и удаляют текст посимвольно: ориентир — 60 WPM (около
5 символов в секунду), с небольшими паузами между словами и предложениями.
Можно остановить сценарий и самостоятельно редактировать любой из двух видов.
Симуляция не забирает фокус; ручной ввод отменяет запланированный набор этого участника.

**Это имитация сети в одном браузере.** Здесь нет действующего WebSocket-сервера,
общей комнаты между вкладками, авторизации или сохранения после перезагрузки.
Каждый участник имеет отдельный Y.Doc; сообщения проходят через отдельную
копию на имитируемом сервере, с задержками, повторами и перестановкой доставки.

## Запуск

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Нужен Node.js >=22.12. Версии зависимостей зафиксированы в lockfile.

- **Run / Pause collaborators** — сценарий, где действия зависят от реально
  полученных изменений других участников.
- **Hold network** — задержать доставку, продолжая локально редактировать.
- **Deliver in reverse** — отправить очередь в обратном порядке, включая дубликаты.
- **Race two edits** — две вставки в одно место до получения чужой правки.
- **Tag selection** — закрепить тег за выделенным текстом. При удалении всего
  диапазона тег перестаёт отображаться.
- **⌘+/ или Ctrl+/** — ввод комментария в пузыре собственного курсора.
  **Escape** возвращает фокус в текст. Комментарий остаётся на 30 секунд;
  в содержимое документа он не попадает. Есть и кнопка для сенсорного ввода.
- Аватар и цвет курсора видны постоянно, имя раскрывается при наведении / фокусе.
  При комментировании единственный аватар отлетает к дальнему углу растущего
  контейнера с текстом; цветная каретка остаётся на месте. После истечения
  комментария аватар возвращается. У границ и соседних пузырей связь сохраняет
  тонкая соединительная линия, а reduced motion отключает перелёт.

## Разделение ответственности

```text
DemoRoom / имитируемый сервер
  ├── Replica Maya (Y.Doc)
  ├── Replica Leo  (Y.Doc)
  └── Replica Nora (Y.Doc)
           │ snapshots + события
           ▼
     Effector model
           │
           ├── reflect → текст, имя, цвет, avatarSrc, состояние комментария
           └── withImperativeEvents → sync / focus документа, move курсора
                         │
                         ▼
                 React Views + локальные DOM refs
```

- `src/collaboration/replica.ts` — CRDT-правки, относительные позиции, теги и presence.
- `src/collaboration/room.ts` — очередь сети, серверная копия, heartbeat и сценарий.
- `src/model.ts` — scoped Effector-модель; сообщения от закрытой сессии отбрасываются.
- `src/bindings.tsx` — подключения через Reflect и withImperativeEvents.
- `src/components/` — React-компоненты документа, курсоров и геометрии; они не
  импортируют Effector или Reflect и не подписываются на сеть.

Документ передаётся через props как долговечное состояние. Imperative-события
обновляют геометрию / фокус / выделение. Пропущенное событие не теряет документ:
при mount View получает актуальный snapshot. DOM-геометрия измеряется после commit,
прокрутки, изменения ширины и загрузки локальных шрифтов.

## Почему позиции и правки не расходятся

| Ситуация                                                        | Правило                                                                                                                                                           |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Одновременные вставки / удаления                                | Yjs объединяет операции; повторная доставка идемпотентна.                                                                                                         |
| Пользователь вводит в старую отображённую версию                | Правка строится на сохранённой CRDT-копии именно этой версии, затем объединяется с новыми операциями. Весь актуальный документ старой строкой не заменяется.      |
| Удаление диапазона при ещё не отображённой чужой вставке внутри | Удаляются элементы исходной версии; чужая вставка, которой там не было, сохраняется.                                                                              |
| Сдвиг текста перед курсором / тегом                             | Y.RelativePosition привязан к элементам CRDT, а не к устаревшему числовому offset.                                                                                |
| Presence пришёл раньше нужных элементов текста                  | Неизвестный anchor не рисуется в неверном месте; он разрешается после нужного document update.                                                                    |
| Старый / повторный presence                                     | Проверяются session и монотонный sequence. Reset создаёт новое поколение; старый input и задержанные пакеты предыдущего поколения отбрасываются.                  |
| Зависшая сеть                                                   | Heartbeat раз в 5 секунд; курсоры с lease старше 15 секунд скрываются. Очередь presence объединяется до последнего пакета, документные операции не отбрасываются. |
| Поздний пакет комментария                                       | Состояние имеет sequence и срок действия по общим часам симулятора. Истёкший комментарий не показывается даже до прихода очистки.                                 |
| Поздний React-render                                            | Доставка и измерения проверяют версии snapshot и реально отображённого текста.                                                                                    |
| IME-композиция при удалённой правке                             | Локальный composing text сохраняется до compositionend, затем сливается с исходной версией; завершающий input не применяется дважды.                              |

Клиенты используют общую начальную CRDT-историю. Нельзя независимо вставить
начальный текст на каждом клиенте: это были бы три разные конкурентные вставки.
Курсор прикреплён к левому соседу; начала тегов — к правому, концы — к левому.
Это явно определяет поведение вставок на границах тегов.

Это лабораторный textarea binding: для каждого input создаётся временная Y.Doc
из снимка. История ограничена 64 версиями, текст — 12 000 UTF-16 code units.
Если снимок уже вытеснен, ввод отвергается с сообщением и View обновляется,
а не перезаписывает новый текст. Для большого редактора нужен специализированный
binding (например, для CodeMirror), undo, восстановление соединения и персистентность.
CRDT гарантирует сходимость, но не выбирает смысловую «лучшую» из двух конкурирующих
замен: оба пользовательских намерения могут остаться в тексте.

Основа: [Yjs document updates](https://docs.yjs.dev/api/document-updates),
[relative positions](https://docs.yjs.dev/api/relative-positions).
Для реального сервера transport должен согласовывать state vectors при reconnect,
проверять документ / сессию / автора, валидировать сообщения и нормализовать TTL
по серверным часам. Текущая тестовая перестановка сообщений намеренно жёстче
обычного упорядоченного WebSocket-соединения.

## Откуда withImperativeEvents

Оператор пока экспериментальный, из [PR #1 форка Reflect](https://github.com/ggkguelensan/reflect/pull/1).
Базовый Reflect установлен из npm. Только три файла optional-оператора включены
как **генерируемая копия фиксированного commit** из форка, с заголовками источника.
Vite alias и TypeScript paths направляют импорт `@effector/reflect/imperative`
на эту копию. Это не утверждение, что подмодуль уже опубликован в npm.

```sh
pnpm vendor:reflect
```

Авторитетный источник — fork; не редактируйте `src/vendor/` самостоятельно.
Build не требует доступа к GitHub: копии уже сохранены в репозитории. Ревизия
задана только в `scripts/vendor-reflect.mjs`. Демо и зависимости Yjs не входят
в PR оператора.

## Проверки

```sh
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:browser
```

Тесты модели проверяют сходимость, устаревший ввод, удаление поверх конкурентной
вставки, anchors, теги, presence leases, TTL комментариев и reset. Chromium-тесты
проверяют два вида, клавиатурное выделение, комментарий по shortcut / Escape,
30 секунд, реакцию ботов, hover и ширину 390px. В CI также проверяется форматирование.

## Vercel

Импортируйте этот GitHub-репозиторий в Vercel. Framework: **Vite**, build command:
`pnpm build`, output: `dist`. Это уже задано в `vercel.json`. Секреты и backend
для текущего демо не нужны. Рекомендуемая версия Node — 24.x.

[Vercel: Vite](https://vercel.com/docs/frameworks/frontend/vite).
Публикация на Vercel не превращает локальный симулятор в общий сервер: каждый
посетитель получает собственную независимую демонстрацию.
